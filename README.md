# Трекер задач АР ВЭД — документация

Персональный трекер задач в виде канбан-доски. Единственный источник правды —
Google Таблица; вокруг неё построены три независимых интерфейса.

## 1. Обзор системы

| Интерфейс | Где живёт | Доступ к данным | Кто может пользоваться |
|---|---|---|---|
| Десктоп | Локально на ПК (Flask, localhost:5000) | SQLite-кэш ↔ Google Sheets (фоновая синхронизация) | Только на этом ПК |
| Мобильный (PWA) | GitHub Pages (статика) | Напрямую Google Sheets API, вход через Google-аккаунт (OAuth) | Только владелец таблицы |
| Публичный отчёт | GitHub Pages (статика) | Зашифрованный локальный снапшот, без обращения к Sheets | Любой, у кого есть ссылка и пароль |

Десктоп и мобильная версия читают/пишут в одну и ту же таблицу и видят изменения
друг друга (с задержкой в пределах ~10 секунд на стороне ПК). Публичный отчёт —
снимок на момент публикации; обновляется автоматически при закрытии задачи
(см. п. 2.3) либо вручную по кнопке.

## 2. Архитектура

### 2.1 Десктоп

- **Flask-сервер** (`server.py`) слушает `localhost:5000`.
- **SQLite (`tracker.db`)** — основное хранилище для интерфейса. Все действия
  в UI идут сюда мгновенно, независимо от наличия сети.
- **Фоновый поток** каждые 10 секунд:
  1. отправляет несинхронизированные локальные изменения в лист `Tasks`;
  2. подтягивает то, что изменилось в самой таблице (например, правки руками
     или с телефона);
  3. синхронизирует справочник тегов с листом `Tags` (слияние по объединению
     множеств — удаление тега с одной стороны не удаляет его с другой).
- Если сети нет — приложение продолжает работать полностью офлайн, очередь
  несинхронизированного просто растёт до восстановления связи.
- **Архивация старых задач** (кнопка «🗄 Архивировать старые» на странице
  аналитики): закрытые задачи (`Выполнено`/`Заблокировано`) с датой закрытия
  старше 1 года переносятся на отдельный лист `Архив` в той же таблице и
  удаляются из `Tasks` и локальной базы. Открытые задачи не архивируются
  никогда, независимо от возраста. Перед переносом показывается количество
  задач и просится подтверждение. Без связи с таблицей архивация не
  выполняется (чтобы не потерять данные без переноса).
- **Запуск:** `start_tracker.bat` → `tray_app.py` → иконка в трее, без окна
  консоли. Для отладки можно запускать `python server.py` напрямую (тогда видно
  ошибки в консоли).

### 2.2 Мобильный (PWA)

- Статические файлы, захостены на GitHub Pages (публичный репозиторий).
- Ходит в Google Sheets API **напрямую из браузера**, без какого-либо бэкенда.
- Авторизация — OAuth через Google Identity Services (тем же аккаунтом, что
  создавал таблицу). Токен живёт около часа, хранится в `localStorage`
  телефона (переживает закрытие приложения, но не переживает истечение срока
  действия — тогда нужно войти заново).
- Устанавливается на домашний экран Android через «Добавить на главный экран»
  в Chrome — работает как отдельное приложение, без адресной строки браузера.
- Функциональность идентична десктопу (канбан, теги, приоритеты, подзадачи,
  чек-лист в примечаниях, аналитика, недельное планирование), кроме двух
  вещей: drag-and-drop не реализован (смена статуса/даты — через открытие
  карточки), и справочник тегов управляется прямо внутри карточки, без
  отдельного окна. Мобильная аналитика может только редактировать уже
  существующие задачи — создавать новые с неё нельзя (для этого доска или
  планирование).

### 2.3 Публичный отчёт

- `report.html` — статическая страница, не требует входа в Google вообще.
- Снимок задач берётся из локальной SQLite на ПК (актуален независимо от
  того, с какого устройства пришло последнее изменение), шифруется (AES-GCM,
  ключ через PBKDF2 из пароля) и сохраняется в `report-data.json` локально в
  папке `public-report/`.
- **Автопубликация:** при закрытии любой задачи (создание сразу в статусе
  «Выполнено»/«Заблокировано», смена статуса на десктопе, либо закрытие с
  телефона, подхваченное десктопом при очередной синхронизации) публикация
  запускается сама, с небольшой отложенной паузой — если закрытий несколько
  подряд, в GitHub уходит один коммит, а не по коммиту на каждое закрытие.
  Включается/выключается тумблером «Автопубликация» на странице аналитики;
  там же виден статус последней публикации.
- Кнопка «🔒 Опубликовать» на странице аналитики — та же публикация вручную,
  в любой момент.
- Если настроен `github_token.txt` — сервер сам заливает файл в GitHub через
  Contents API. Если нет — файл нужно залить в репозиторий вручную (и
  автопубликация просто не публикует наружу, оставляя локальный файл
  обновлённым).
- Получатель открывает ссылку, вводит пароль — расшифровка происходит
  **в его браузере**; сам пароль никуда не передаётся и не хранится на его
  стороне. Карточки открываются только на просмотр, без полей ввода; для
  задачи с подзадачами показывается связь и можно перейти между ними.
- Пароль отчёта задаётся один раз («🔑 Пароль отчёта») и хранится локально в
  `report_password.txt` — при последующих публикациях вводить его заново не
  нужно, только при явной смене.

## 3. Структура данных (Google Таблица)

### Лист `Tasks` — колонки A:L

| # | Колонка в таблице | Название в интерфейсе | Формат | Описание |
|---|---|---|---|---|
| A | `id` | — | число (текст) | Последовательный ID, генерируется автоматически |
| B | `Задача` | Задача | текст | Текст задачи |
| C | `Статус` | Статус | текст | Один из шести: `Бэклог`, `Не начато`, `Выполняется`, `На паузе`, `Заблокировано`, `Выполнено` |
| D | `Проект` | **Процесс** | текст, через запятую | Один или несколько тегов из справочника |
| E | `Подпроект` | **Проект** | текст, через запятую | Один или несколько тегов из справочника |
| F | `Приоритет` | Приоритет | текст | `Критично` / `Высокий` / `Средний` / `Низкий` |
| G | `Дата закрытия` | Дата закрытия | дд.мм.гггг | Проставляется автоматически при первом попадании в закрывающий статус (см. п. 4), редактируется вручную |
| H | `Создано` | Создано | дд.мм.гггг | Дата создания задачи, не редактируется |
| I | `Примечания` | Примечания | текст | Свободный текст. Нумерованные строки (`1.`, `2.`…) автоматически становятся чек-листом; отмеченный пункт хранится обёрнутым в `~~текст~~` |
| J | `№ заявки` | № заявки | текст | Read-only в интерфейсе — извлекается автоматически из текста примечаний по паттерну `ЗР` + 9 цифр |
| K | `Актуально` | Актуально | дд.мм.гггг | Дата «актуальности» задачи — используется для недельного планирования и общего фильтра на доске. По умолчанию = дате создания, двигается вручную (кнопка «Сегодня») |
| L | `Родитель` | — | `id` родительской задачи | Пусто у обычных задач. Заполняется автоматически при создании через «+ Подзадача» в карточке родителя |

Названия колонок в таблице («Проект», «Подпроект») сознательно не совпадают с
названиями полей в интерфейсе («Процесс», «Проект») — переименовывались только
подписи в UI, физическую структуру таблицы не трогали.

### Лист `Tags`

Две колонки: `Категория` (`Проект` или `Подпроект`) и `Значение`. Общий
справочник тегов, доступный и десктопу, и мобильной версии. Создаётся
автоматически при первом обращении, если ещё не существует.

### Лист `Архив`

Те же колонки A:L, что и `Tasks`. Сюда переезжают старые закрытые задачи при
ручной архивации (см. п. 2.1). Создаётся автоматически при первом обращении.

## 4. Ключевая логика

- **Закрывающие статусы** — `Выполнено` и `Заблокировано`. При переходе в
  любой из них из открытого статуса, если `Дата закрытия` ещё не заполнена
  вручную, она автоматически проставляется на сегодня — это работает и при
  смене статуса у существующей задачи, и при создании новой сразу в
  закрывающем статусе. Переключение между самими закрывающими статусами дату
  не трогает.
- **Подзадачи** — одноуровневая связь «родитель → подзадачи» через поле
  `Родитель`. Из карточки обычной задачи (без родителя) доступна кнопка
  «+ Подзадача»: создаёт новую задачу, наследующую Процесс/Проект/Приоритет
  родителя, дальше редактируется как обычная задача. В карточке родителя
  виден список его подзадач (текст + статус) с переходом по клику; в карточке
  подзадачи — ссылка на родителя. У подзадачи своя подзадача не заводится
  (второй уровень вложенности не предусмотрен). В аналитике и в публичном
  отчёте эта связь показывается короткой строкой под названием задачи.
- **Бэклог** — обычный шестой статус в общем списке, физически ничем не
  отличается от остальных. На доске вынесен в отдельную сворачиваемую панель
  слева, не подчиняется общему фильтру по дате «Актуально».
- **Общий фильтр по дате «Актуально»** на доске по умолчанию показывает задачи
  с датой не раньше понедельника текущей недели; задачи без даты вообще не
  прячутся никогда.
- **Недельное планирование** (`planning.html`) — раскладывает по семи дням
  недели все задачи, у которых `Актуально` (либо `Создано`, если поле пустое)
  попадает на этот день. Выполненные и заблокированные задачи в план не
  попадают.
- **Пагинация** — по 25 карточек на колонку/вкладку, кнопки «Ещё 25» и
  «Раскрыть все». При активном поиске лимит снимается — ищет по всем
  карточкам, а не только по загруженным.
- **Поиск** — одно поле, ищет одновременно по тексту задачи и по тексту
  примечаний.
- **Тема** — тёмная/светлая, переключатель в шапке, выбор сохраняется в
  браузере отдельно для десктопа и для мобильной версии.

## 6. Настройка с нуля

1. **Google Cloud проект**: включить Google Sheets API.
2. **Service Account** (для ПК): создать, скачать JSON-ключ → `credentials.json`,
   расшарить Google Таблицу на email service account с правами Editor.
3. **OAuth Client ID** (для мобильной версии): Google Auth Platform → Audience
   → добавить себя в Test users → Clients → создать Web application клиент →
   Authorized JavaScript origins = `https://<username>.github.io` (без пути и
   слеша в конце). Вписать полученный Client ID в `CLIENT_ID` в начале каждого
   мобильного HTML-файла (`index.html`, `analytics.html`, `planning.html`).
4. **GitHub репозиторий**: публичный, файлы мобильной версии — в корне.
   Settings → Pages → Deploy from branch → `main` / `/(root)`.
5. **GitHub-токен** (опционально, для автопубликации отчёта): Fine-grained
   token, доступ только к этому репозиторию, право `Contents: Read and write`
   → сохранить в `github_token.txt` локально на ПК.
6. Указать `SPREADSHEET_ID` (ID таблицы из её URL) в `server.py` и во всех
   мобильных HTML-файлах — должен совпадать везде.
7. В самой Google Таблице на листе `Tasks` должен быть заголовок «Родитель»
   в ячейке `L1` (листы `Tags` и `Архив` создаются кодом сами, а колонка
   `Родитель` — нет, так как это не отдельный лист).

## 7. Обслуживание

- **Обновить код на ПК:** заменить файлы в `Planner`, при необходимости
  `pip install -r requirements.txt` в активированном `venv`, перезапустить
  через трей.
- **Обновить мобильную версию:** заменить файлы в GitHub-репозитории, затем на
  телефоне очистить данные сайта в Chrome (Настройки → Настройки сайтов →
  найти сайт → сбросить) — иначе service worker может отдавать старую
  закэшированную версию.
- **Опубликовать/обновить публичный отчёт:** происходит само при закрытии
  задачи; вручную — страница аналитики на ПК → «🔒 Опубликовать». Пароль
  меняется отдельно кнопкой «🔑 Пароль отчёта» и не требует повторного ввода
  при обычной публикации.
- **Архивировать старые задачи:** страница аналитики на ПК → «🗄 Архивировать
  старые» — с подтверждением количества перед переносом.
- **Перенос на новый ПК:** скопировать всю папку `Planner` целиком, включая
  `credentials.json`; `tracker.db` можно не переносить — пересоздастся сам при
  первом запуске с интернетом.

## 8. Известные ограничения

- Токен на телефоне живёт около часа — при длительной непрерывной работе
  потребуется повторный вход.
- OAuth-приложение в статусе Testing — работает только для аккаунтов,
  явно добавленных в Test users в Google Auth Platform.
- Синхронизация тегов между ПК и Таблицей — это объединение множеств:
  удаление тега на одной стороне не удаляет его на другой при следующей
  синхронизации.
- Автоматического независимого бэкапа самой Google Таблицы нет; ручная
  архивация старых задач (п. 2.1) уменьшает объём данных, но бэкапом не
  является.
- Подзадачи ограничены одним уровнем вложенности — у подзадачи нет кнопки
  создания своей подзадачи.
- Мобильная аналитика не умеет создавать новые задачи, только
  просматривать/редактировать уже существующие.
